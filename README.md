# SDemo.QuickTranslate 翻译助手

一个**后台常驻的托盘翻译工具**：在任何程序中选中文本或图片，按下热键即可通过 **OpenAI 兼容接口**翻译为指定语言，结果以浮窗形式显示在选中内容附近；也可以按 `Ctrl+Alt+I` **弹出置顶输入框**，自己填内容再翻译。WPF + C# 主程序，**C++ 原生库 (SDemo.NativeCore.dll)** 负责系统级操作，两者通过 P/Invoke 互操作。

---

## 功能

- **无主窗口，启动即托盘**：右键托盘图标可进行所有操作。
- **右键菜单**：翻译为中文 / 英文 / 日语、截图翻译、输入翻译、生成回复、首选项、帮助、重启、退出。
- **全局热键**（默认，可在首选项中修改）：
  | 热键 | 功能 |
  |---|---|
  | `Ctrl+Alt+T` | 翻译为中文 |
  | `Ctrl+Alt+E` | 翻译为英文 |
  | `Ctrl+Alt+J` | 翻译为日语 |
  | `Ctrl+Alt+R` | 生成回复 |
  | `Ctrl+Alt+Q` | 截图翻译（**全屏框选区域**后识别） |
  | `Ctrl+Alt+I` | 输入翻译（**弹出置顶输入框**，填入内容后翻译） |
- **输入翻译（手输内容）**：按 `Ctrl+Alt+I` 弹出**始终置顶**的输入窗口，直接在输入框里打字/粘贴，选好目标语言后按 `Ctrl+Enter`（或点「翻译」）即开始流式翻译；`Esc` **关闭窗口并立刻中断正在进行的推理**（点「停止」等效）。目标语言可下拉选择也可直接输入，默认预选这条热键的「目标语言」（默认 `English`；热键没设语言时用上次用过的语言）；点「清空」可换个内容再翻译，窗口可拖动/缩放，关闭时焦点自动还给原来的程序。

- **一键翻译选中内容**：在任意程序中选中文本，按热键即弹出翻译结果浮窗；选中/复制图片时自动识别图片文字。
- **截图翻译（框选）**：按热键时**先把整屏冻结**，随即弹出半透明遮罩、遮罩上显示的就是这张冻结图，**拖拽鼠标框选**要识别的区域（`Esc` / 右键取消），松手直接从冻结图裁剪并翻译——不是选完再截屏，所以框选期间屏幕上的变化（动画 / 视频 / 滚动 / 窗口切换）既不会让「看到的」和「翻译的」对不上，也不会把遮罩或浮窗自己截进去。识别方式遵循该 API 自己的「图片翻译方式」：`视觉模型` = 截图直接发给多模态模型（快、保排版、不做本地 OCR）；`本地 OCR 后翻译` = 先本地识别文字，识别不出时再退回发原图。
- **浮窗会同时给出「原图」**：图片 / 截图翻译时，截图原图直接显示在译文上方（点击右键菜单「复制原图」可复制，`Capture` 始终保留图片本身，不再被 OCR 文本顶掉），因此译文对不对、模型到底看没看到图，一眼可辨。若走了本地 OCR，识别结果会另外放进「原文（本地 OCR 识别）」折叠区。
- **回退原因会写明**：视觉模型拒绝图片时（最常见的是该模型**不支持图片输入**，接口回 `HTTP 400 ... does not support image inputs`），浮窗底部提示条会原样给出接口的真实原因**并说明已回退本地 OCR**——不会只看到「先 OCR 再翻译」而误以为程序默认走 OCR。
- **流式输出**：结果逐字实时显示在浮窗中（长文本自动换行，不撑宽窗口）。**思考过程同样实时流式**：只要模型返回思考内容（`reasoning_content` / `reasoning` / `thinking`），就边生成边追加到「思考过程（实时）」区域，状态栏同步显示「模型正在思考…（已 N 字）」，不会先干等再一次性贴出。
- **翻译默认关闭思考**：请求里同时带上四种「关闭思考」参数——`thinking.type=disabled`（DeepSeek）、`enable_thinking=false`（通义千问）、`chat_template_kwargs.enable_thinking=false`（vLLM / llama.cpp）、`reasoning_effort=none`（LM Studio / OpenAI 风格）。接口一般只认其中一种、忽略其余；整组被拒（HTTP 400）时自动逐个去掉重试，并把可用的那种记住。接口完全不支持关闭思考时，模型仍会思考，此时思考过程会实时显示出来。「生成回复」始终保留思考过程。`Esc` 可随时取消正在生成的请求。
- **「最大输出 Token」真的会生效**：对应接口参数 `max_tokens`（OpenAI 新模型会自动改用 `max_completion_tokens`）。服务端按上限截断时，浮窗会提示「已达上限、输出被截断」；万一服务端忽略该参数，程序还会按增量条数主动停止接收（客户端兜底），确保上限一定生效。
- **浮窗定位**：默认显示在选中内容**上方**，空间不足自动偏移到下方或覆盖，并夹紧在屏幕工作区内；`Esc` 关闭，可拖动。
- **浮窗右键菜单**：复制结果、复制原文、复制原图（有截图时）、翻译为其他语言、重新翻译、生成回复、截图翻译、关闭。
- **图片翻译**：默认把原图发给视觉模型；模型不支持图片时**自动回退本地 OCR**（Windows.Media.Ocr）。可在每个 API 上单独切换。
- **多 API（模型）设置**：可以同时配置任意多个 OpenAI 兼容 API，每个 API 各有**自己的接口地址、API Key、模型列表与请求参数**（温度 / 最大输出 Token / 超时 / 图片翻译方式），互不影响；「模型」页用卡片列出所有提供商，点「编辑」在弹窗里修改、获取模型列表并测试连接，点「移除」删除，底部「＋ 添加模型提供商」新增。**API Key 保存后不再回填显示**：留空 = 保持不变，输入新内容 = 替换。
- **按热键选模型**：先设一个「默认模型」，想换模型的**热键**单独指定 API + 模型即可，优先级 **热键模型 > 默认模型**；热键行上的「模型 ●」按钮就是这项设置，浮窗/输入框上也会标出本次实际使用的「API / 模型」。引用的 API 被删除或没配模型时**逐级回退**并在日志写明，绝不静默用错模型。
- **首选项**：左侧导航（热键 / 模型 / 通用 / 提示词）；热键自定义（可增删多条，**每条热键可单独设置提示词与模型**）、多 API 管理、默认模型、**分功能提示词（翻译 / 生成回复 / 截图翻译）**、开机自启（**默认开启**，每次启动按这里的开关同步注册表，以软件设置为准）等；同一时间只允许打开一个首选项窗口。
- **生成回复 / 输入翻译的语言**：默认「生成回复」热键译成中文、「输入翻译」热键译成英文；每条热键的「目标语言」都可以在首选项里改。浮窗里的「生成回复」按钮沿用触发它的那条热键的语言。
- **提示词**：优先级为「**热键单独设置的提示词 > 功能默认提示词 > 内置默认**」。典型用法：把一条热键的动作设为「生成回复」，再给它单独写一套邮件回复提示词，就得到一条「专门回邮件」的热键；同时再保留一条通用回复热键互不影响。
- **打开首选项时暂停全局热键**：避免录入热键时触发已有热键（冲突），关闭窗口后自动恢复（恢复失败会在托盘气泡提示）。
- **淡蓝主题界面**：统一的淡蓝配色 + 圆角控件（按钮、输入框、下拉框、复选框、单选框、标签页、滑块、滚动条、进度条），主题集中在 `src/SDemo.QuickTranslate/Themes/LightBlue.xaml`，改这一个文件即可换肤。

## 项目结构

```
QuickTranslate/                      # 仓库根目录（GitHub 仓库名同为 QuickTranslate）
├── SDemo.QuickTranslate.slnx        # VS 解决方案（含 C++ 与 C# 两个项目）
├── build.ps1 / build.cmd            # 一键构建
├── README.md
├── assets/app.ico                   # 应用/托盘图标
├── scripts/make-icon.ps1            # 图标生成脚本
└── src/
    ├── SDemo.NativeCore/            # ★ C++ 原生库（C API，供 C# P/Invoke 调用）
    │   ├── SDemo.NativeCore.h       #   接口声明
    │   ├── SDemo.NativeCore.cpp     #   Win32：模拟 Ctrl+C、剪贴板、屏幕截图、窗口/光标信息
    │   ├── OcrCppWinrt.cpp          #   C++/WinRT：Windows.Media.Ocr 文字识别
    │   ├── SDemo.NativeCore.vcxproj #   MSBuild 工程（VS 2026 / v145）
    │   └── CMakeLists.txt           #   备用 CMake 构建
    └── SDemo.QuickTranslate/        # ★ WPF + C# 主程序
        ├── App.xaml(.cs)            #   入口：托盘 + 热键 + 编排
        ├── Native/                  #   user32 P/Invoke + SDemo.NativeCore.dll 封装（含托管回退）
        ├── Models/                  #   设置、热键、捕获结果
        ├── Services/                #   设置持久化、热键管理、托盘、选中捕获、OCR、API 客户端、编排
        ├── Themes/                  #   淡蓝主题（配色 + 圆角控件样式）
        └── Views/                   #   首选项窗口、翻译结果浮窗、输入翻译窗口、截图框选遮罩、提示词编辑器、模型选择对话框、帮助窗口
```

**C++ / C# 混编方式**：`SDemo.NativeCore.dll` 以 C ABI 导出函数，C# 通过 `[DllImport]` 调用（见 `src/SDemo.QuickTranslate/Native/SDemoNativeCore.cs`）。原生库缺失或调用失败时**自动回退**到托管实现，应用仍可正常工作。想扩展 C++ 能力，只需在 `SDemo.NativeCore.cpp` 添加导出函数并在 `SDemoNativeCore.cs` 添加对应声明。

## 环境要求

- **构建**：Windows 10/11 + Visual Studio（含 **C++ 桌面开发** 与 **.NET 桌面开发** 工作负载）+ .NET 9 SDK。
- **运行**：Windows 10 1809+；默认发布为**框架依赖**版本（需 [.NET 9 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/9.0)），也可用 `-SelfContained` 发布为免安装版本。

## 构建

```powershell
# 一键构建并发布（框架依赖）到 dist\SDemo.QuickTranslate
.\build.ps1

# 或自包含免安装版本
.\build.ps1 -SelfContained

# 或仅编译不发布
.\build.ps1 -NoPublish
```

也可直接用 VS 打开 `SDemo.QuickTranslate.slnx` 编译（注意：C# 项目通过 csproj 自动复制原生 DLL，若提示缺少 SDemo.NativeCore.dll，先单独编译 SDemo.NativeCore 项目或运行 build.ps1）。

> 发布目录里生成的可执行文件名为 `QuickTranslate.exe`（程序集与命名空间仍是 `SDemo.QuickTranslate`），exe 已内嵌应用图标，资源管理器与任务栏都能看到。

## 使用步骤

1. 运行 `QuickTranslate.exe`，右下角托盘出现图标。
2. 右键托盘图标 → **首选项 → 模型**：在「模型提供商」卡片底部点「＋ 添加模型提供商」（新添加时可先选预设），在弹窗里填好**显示名称**、**接口地址**与 **API Key**，再点 **「获取模型列表」**把可用模型拉进列表；去掉不用的模型，在「首选模型」里挑一个，保存退出。最后在「默认模型」卡里选定 **哪一家的哪个模型作为默认**，保存即可。
   - 支持任意 OpenAI 兼容接口：OpenAI、DeepSeek、通义千问、智谱、Ollama、LM Studio 等；**可以添加多个**，每个 API 的地址 / Key / 模型 / 参数各存一套，互不影响。
   - 不知道模型名？填好「接口地址」与「API Key」后点 **「获取模型列表」**，程序会调用 `GET {接口地址}/models` 拉取可用模型并**清空旧列表后重新填入**模型列表（同时兼容 Ollama 的 `{models:[{name}]}` 返回格式），选中后保存即可；也可以手动输入模型名。拉取到的列表会缓存到设置里，下次打开可直接选择。
   - 「测试连接」会先 `GET /models` 校验地址与 Key，再用一次最小对话请求验证模型真的能应答，失败原因（HTTP 状态与接口返回的错误信息）直接显示在按钮下方。
   - 想让日常翻译用便宜的快模型、截图翻译用能看图的视觉模型？在「模型」页添加两个 API 并选好「默认模型」，再到「热键」页给对应热键点「模型」单独指定（优先级 **热键模型 > 默认模型**）。
3. 在任意程序里**选中文本**（或选中/复制图片），按下热键（如 `Ctrl+Alt+T`）。
4. 翻译浮窗出现在选中内容附近（流式逐字显示、长文本自动换行；模型若在思考，「思考过程（实时）」会同步逐字增长），`Esc` 关闭，右键浮窗可复制 / 重新翻译 / 生成回复 / 切换语言。
5. 想让某条热键用专门的提示词（例如邮件回复）：首选项 → **热键** → 该行「提示词」按钮填写；各功能的公共默认写在 **提示词** 标签页。
6. 想让某条热键用专门的回复语言：直接改那条热键的「目标语言」（默认「生成回复」是 `中文`，例如改成 `English` 就是一条英文回邮件的热键）。
7. 截图翻译：按热键后拖拽框选区域即可；发图还是先 OCR 由**该 API 自己的**「图片翻译方式」决定（首选项 → 模型）。
8. 输入翻译：按 `Ctrl+Alt+I` 弹出**置顶**输入窗口 → 在「要翻译的内容」里输入/粘贴文字 → 选择（或直接输入）目标语言 → `Ctrl+Enter` 或点「翻译」；译文与思考过程边生成边显示；`Esc` 关闭窗口**并中断推理**。

## 常见问题

- **热键被占用**：首选项中修改为该组合；注册失败时托盘会气泡提示。
- **图片翻译失败**：默认走视觉模型；若模型不支持图片会自动回退本地 OCR。可切换「本地 OCR 后翻译」；此时若 OCR 失败/被中断，也会自动改发原图给视觉模型，尽量保证翻译继续。
- **明明选了多模态模型，为什么还是先 OCR 了**：先看浮窗底部提示条和日志里的 `视觉模型直发（未做本地 OCR）` / `视觉模型不接受图片，回退本地 OCR`。程序**默认就是直发原图**，只有当接口明确拒绝图片时才会回退 OCR，最常见的拒绝理由是「这个模型不支持图片输入」（例如 LM Studio 里只加载了文本权重、没加载视觉投影 `mmproj`，或该模型本身是纯文本模型）。可在 LM Studio 里用 `GET /api/v0/models` 看 `type`：`vlm` 才能看图，`llm` 不行。此时程序能做的只有本地 OCR——想保留排版/直接读图，请换成真正的视觉模型。
- **本地 OCR 无结果**：需系统安装相应语言包（Windows 设置 → 时间和语言 → 语言 → 添加语言）；无结果时自动回退视觉模型。
- **OCR 过程中被打断会不会中断翻译**：不会。OCR 的任何异常都会被吞掉并记录日志，随后自动改发原图给视觉模型继续翻译。
- **原文里有 `Suzuki-san` 这类日语痕迹，结果整段变成日文**：内置翻译提示词只加了一条限制——**输出必须整段是目标语言**（不得用原文语言回复，也不得中途换语言）；目标语言会先经 `OpenAIClient.DescribeLanguage` 写全（`中文` → `Simplified Chinese (简体中文)`、`繁體中文` → `Traditional Chinese (繁體中文)`、`日本語` → `Japanese (日本語)` 等），避免模型把「中文」当成日文汉字。自定义提示词会**完全接管**内置提示词，如果自己改过提示词，需要在里面同样写明目标语言。
- **翻译时总是先思考很久 / 看着不像流式**：翻译请求默认同时带上四种「关闭思考」参数（DeepSeek 的 `thinking`、通义千问的 `enable_thinking`、vLLM/llama.cpp 的 `chat_template_kwargs`、LM Studio/OpenAI 风格的 `reasoning_effort=none`），通常能让模型直接吐译文、逐字增长。若接口完全不支持关闭思考，思考过程会**实时**显示在浮窗里（能看到进度、不会再像卡住），这种情况下建议换非思考型模型（如 `deepseek-chat`、`qwen-plus`）。
- **最大输出 Token 好像没生效**：该值会作为 `max_tokens` 发给接口；思考过程同样计入这个额度，所以「思考用光了额度、正文没出来」时看起来像没生效——浮窗会明确提示「已达上限、输出被截断 / 只输出了思考过程」，调大该值即可。若服务端忽略该参数，程序会按增量条数主动停止接收，保证上限生效。
- **按热键没翻译选中的内容 / 时好时坏**：已修。三个原因都处理了：① 剪贴板旧内容被误当成选中内容（现在必须 `Ctrl+C` 真的复制到新内容才算数）；② 旧弹窗还占着焦点时捕获（现在会先等焦点回到你原来的程序再捕获）；③ 上一次请求还在跑时静默忽略热键（现在会**打断上一次并立即执行新的**，日志里有 `打断上一次操作`）。
- **连续快速按热键没反应**：现在不会再被忽略，第二次会打断第一次并重新翻译；不想被打断就等结果出来再按。
- **「获取模型列表」失败**：先确认「接口地址」指向 OpenAI 兼容地址（OpenAI 官方为 `https://api.openai.com/v1`，DeepSeek 为 `https://api.deepseek.com`），程序会请求 `{接口地址}/models`；若服务端不提供该接口（部分自建网关），直接在「首选模型」框里手动输入模型名即可。
- **「测试连接」报“没有内容/没有找到内容”**：多是模型把 token 全用在思考上导致正文为空（思考型模型常见）。现在测试会用足够的最小请求、同样优先关闭思考（并在结果里告诉你用的是哪种关闭方式），并识别思考内容后按实际情况提示；正式翻译请把「最大输出 Token」留足余量。
- **浮窗只显示了思考、没有译文**：说明模型这次只输出了思考过程（思考内容已实时显示在浮窗里），额度被思考用完了。程序会提示「可加大最大输出 Token」而不是报错；也可在首选项 → 通用 关掉「翻译时关闭思考」查看完整过程，或换用非思考型模型。
- **截图翻译是发图还是先 OCR**：由**当前这次请求所用 API** 的「图片翻译方式」决定（首选项 → 模型），`视觉模型` 就直接把截图发给模型（日志写 `视觉模型直发（未做本地 OCR）`），`本地 OCR 后翻译` 才先识别文字（日志写 `OCR 结果: 长度=…`）。
- **截图翻译截到的位置不对**：`Ctrl+Alt+Q` 是全屏框选，拖拽到哪里就截哪里；`Esc` 或右键取消，误点一下也会取消。
- **生成回复用什么语言**：用该热键自己的「目标语言」，默认是 `中文`（可在首选项 → 热键里改）；没设语言的热键则跟随原文语言。
- **输入翻译窗口怎么用 / 为什么是置顶的**：`Ctrl+Alt+I`（或托盘菜单「输入翻译」）弹出输入窗口，它声明了 `Topmost`（始终置顶），不会被别的窗口盖住；输入内容后 `Ctrl+Enter` 翻译。目标语言默认预选 `English`（默认「输入翻译」热键的目标语言），也可以在窗口里临时切换；若这条热键自己设了「目标语言」则以它为准。**翻译过程中按 `Esc` 会立刻中断本次推理并关闭窗口**（点「停止」等效，已生成的部分会保留在窗口里）；窗口关闭后焦点自动还给原来的程序，不影响下一次「选中即翻译」。
- **升级后为什么多了一条 Ctrl+Alt+I 热键**：这是「输入翻译」功能的默认热键，首次加载老配置时会自动补上（只补一次，之后在首选项里删掉就不会再加回来）。用不到可以在首选项 → 热键里改键或直接禁用。
- **配置存放位置**：`%APPDATA%\SDemo\QuickTranslate\settings.json`；日志在 `%APPDATA%\SDemo\QuickTranslate\logs\`（含捕获方式、截图选区尺寸、OCR 长度、首字耗时、思考长度等，便于排查）。

> **排查小工具**：
> - `QuickTranslate.exe --diag`：选中一段内容后运行，会自动连续捕获两次，并把前台窗口信息与捕获结果写入日志，用于确认捕获链路是否正常。
> - `QuickTranslate.exe --selftest [--to=English] [--tokens=64] [--think] [--reply] [--base=...] [--model=...] [--text="..."]`：**无界面自检**，直接把一段文字走一遍流式翻译/生成回复，把「实际生效的关闭思考参数、思考与正文各自的首个增量时间点、增量条数、finish_reason、是否被截断」写进日志（正文同时写入 `%TEMP%\sdemo-selftest-result.txt`），退出码 0 表示拿到了正文。用来快速确认「思考到底关掉没有 / 是不是真流式 / 最大输出 Token 生效没有」。
> - `QuickTranslate.exe --window=prefs|models|help|popup|input`：只打开指定窗口（首选项 / 首选项的「模型」页 / 帮助 / 示例翻译浮窗 / 示例输入翻译窗口，后两者带实时思考与「已达上限」提示条），不注册托盘与热键，用于界面调试与截图，关闭窗口即退出。`--window=input` 打开的是**可用**的输入翻译窗口（配置已加载，可以直接输入内容翻译，用来端到端验证）。

## 技术说明

- **DPI**：系统 DPI 感知（manifest），坐标换算统一处理物理像素与 WPF DIP。
- **选中内容捕获**：优先 UI Automation 的 **TextPattern 真实选中**（不干扰剪贴板）；再退到「模拟 Ctrl+C → 剪贴板序号必须变化才认 → 恢复剪贴板」；最后才在单行输入框（Edit/ComboBox，长度受限）取整个内容兜底。捕获**之前**会等前台窗口不再是本程序，避免读到自己弹窗。
- **截图翻译**：`Views/ScreenCaptureWindow.xaml` 提供全屏半透明遮罩 + 拖拽框选（`CombinedGeometry` 挖洞显示选区），选区按 DIP↔物理像素换算后由 `SDemo.NativeCore.SDemoCaptureScreenToBmp` 截取；截图在遮罩关闭、浮窗创建**之前**完成，避免把自身界面截进图里。
- **关闭思考**：翻译类请求一次性带上 `thinking.type=disabled`、`enable_thinking=false`、`chat_template_kwargs.enable_thinking=false`、`reasoning_effort=none` 四种参数（不同服务端认的不同，不认识的参数一般被忽略）；接口返回 400/422 时按「逐个去掉」的顺序重试，可用的组合按 `地址|模型` 缓存，后续请求直接用，不再试错。全都不可用时照常请求（模型仍会思考），此时思考过程实时显示。实现见 `OpenAIClient.ThinkOffProfiles`。
- **提示词解析**：`TranslateController.ResolvePrompt(热键提示词, 功能默认提示词)` 决定本次请求的 system 提示词（热键单独设置 > 功能默认 > 内置默认，自定义提示词完全接管内置提示词）；内置翻译提示词由 `OpenAIClient.TranslateSystemPrompt(语言, 是否图片)` 生成，先用 `DescribeLanguage` 把语言名补全（`中文` → `Simplified Chinese (简体中文)`，避免模型把「中文」当成日文汉字），再锁定输出语言（输出必须整段是目标语言，不得用原文语言回复，也不得中途换语言）。思考内容始终从接口读取并**实时显示**（翻译与生成回复一样），正文为空时提示可调大「最大输出 Token」。
- **输入翻译**：`Views/InputTranslateWindow.xaml(.cs)` 是独立的置顶窗口（`Topmost=True`，非模态），由 `TranslateController.ShowInputTranslate` 打开/复用，窗口内自己持有一个 `CancellationTokenSource`：`Esc` / 「停止」/ 关闭窗口 / 再按其它热键都会 `Cancel()`，从而立刻中断流式推理（`TranslateController.CancelCurrent` 会一并取消它）。流式展示与「最大输出 Token 截断」提示走的是同一份代码——`PopupWindow` 与它都实现 `Views/IStreamSink.cs`，`TranslateController.StreamIntoAsync` 只认这个接口。
- **OCR**：优先 C++/WinRT 原生实现，回退到 C# 托管 WinRT。
- **多 API 与模型解析**：`Services/ApiCatalog.cs` 负责把一次请求解析成具体的「API + 模型」：`Resolve(热键条目)` 按 **热键模型 → 默认模型 → 第一个可用 API** 逐级查找（前一级引用的 API 被删/模型为空时回退并在日志写明，找不到任何可用模型才抛错），并按「API + 模型 + 参数」缓存 `OpenAIClient`（改设置后 `Clear()` 失效，避免每次请求新建 `HttpClient`）。每个 `ApiProvider` 自带地址 / Key / 模型列表 / 温度 / 最大输出 Token / 超时 / 图片翻译方式，因此不同功能可以走不同服务端。设置结构见 `Models/AppSettings.cs`（旧的单 API 字段 `api` 仍保留并在保存时同步成「默认模型」，保证旧版本可读、`--selftest` 可用）。
- **API**：`POST {BaseUrl}/chat/completions`，支持文本与多模态（图片 base64）消息；默认 `stream=true` 流式返回，SSE 增量同时解析正文与思考字段（`reasoning_content` / `reasoning` / `thinking`），并读取 `finish_reason` 与 `usage`。`max_tokens` 被服务端忽略时按增量条数在客户端兜底截断；超过「超时」秒没有任何新数据则中止并提示，避免界面无限转圈。模型列表通过 `GET {BaseUrl}/models` 获取。
- **界面主题**：所有控件样式集中在 `Themes/LightBlue.xaml`（`App.xaml` 中以 `MergedDictionaries` 引入），采用 WPF 控件模板重写实现圆角与淡蓝配色，不依赖第三方 UI 库。
- **命名空间**：C# 统一使用 `SDemo` 前缀，根命名空间为 `SDemo.QuickTranslate`（子命名空间 `SDemo.QuickTranslate.Models` / `.Services` / `.Views` / `.Native`），XAML 的 `x:Class` 与之对应；项目文件、程序集与可执行文件名也已统一为 `SDemo.QuickTranslate`。
